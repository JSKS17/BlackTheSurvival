# D 카드 중복 생성 수정

## 원인과 재현

`BeginCardChoice`는 대상 선택(수아 W·시셀라 E), 충전, 예견, 희생 선택을 정확한 사본 단위로 처리하려고 손패의 일반 ID를 `~u` 개별 식별자로 바꾼다. 예견은 뽑을 카드 더미의 후보도 식별한다. 이 과정의 `IdentifyChoiceCopy`가 영구 덱의 D 사본은 바꾸면서 `weaponGrantedCards`의 장비 지급 기록은 일반 ID로 남겼다.

다음 전투 시작·장비 변경·전투 밖 저장 복원에서 `SyncWeaponCards`는 이전 일반 ID를 찾지 못하고 새 D를 추가했다. 기존 개별 D는 독립 획득 사본으로 취급되어 모닥불에서 제거할 수 있었다. 선택창에서 실제 기술을 사용하지 않고 취소해도 발생한다.

수정 전 실제 회귀 결과: 프라가라흐를 장착한 덱 4장에 수아 W와 D를 함께 손패에 넣고 선택창을 열었다 취소한 뒤 전투 밖 동기화를 실행하면 **덱 4→5장, 단검 D 1→2장**이 되었다.

## 수정

- 개별 식별자를 부여하기 **전** 영구 덱의 해당 사본이 장비 지급 사본인지 확인하고, 해당 지급 기록 한 개도 같은 식별자로 갱신한다. 같은 종류의 독립 획득 사본이 먼저 있으면 그 사본을 장비 지급으로 바꾸지 않는다.
- 장비 동기화는 정확한 지급 참조만 제거한다. 같은 무기군이 계속 장착되면 이전의 개별 참조와 과거 강화 상태를 재사용한다.
- 이전 버전의 저장된 전투에서 지급 기록의 정확한 참조만 빠졌으면 아직 연결되지 않은 같은 종류의 개별 사본에 기록을 다시 연결한다. 카드를 추가하거나 삭제하지 않고 전투 더미·난수도 보존한다.
- 지급 기록이 없던 옛 저장은 알렉스의 추가 D도 포함하여 현재 덱에서 장비 지급 사본을 추정한다.

무기 2개, 알렉스의 추가 D, 정상 획득·복제 사본은 그대로 허용한다. 현재 모든 D의 원본 코스트는 2 이상이어서 코스트 1 이하 카드 복제 조우로는 새 D를 만들 수 없지만, 조건을 충족하는 D의 복제를 허용하던 기존 규칙은 변경하지 않았다.

이미 다음 동기화를 거쳐 일반 D와 개별 D가 모두 남은 옛 저장은, 정상 획득 사본을 식별한 저장과 데이터가 같을 수 있다. 카드 손실을 피하려고 이런 사본을 자동 삭제하지 않는다. 장비 지급 사본 이외의 D는 기존 모닥불 제거 기능으로 정리할 수 있다.

## 검증

`Tools/WeaponGrantIntegritySmokeTests.cs`와 `Tools/RunCoreTests.ps1 -WeaponGrantsOnly`는 실제 선택창 열기·취소 API로 원인을 재현하며 다음을 검증한다.

- 대상 2종·충전·예견·희생 선택창 뒤 저장 복원과 반복 동기화에서 덱 수량 유지.
- 예견의 뽑을 카드 후보에 있던 장비 D의 지급 참조 갱신.
- 같은 무기 2개, 같은 종류의 독립 획득 D, 독립 사본 제거 및 장비 사본 보호.
- 알렉스 4개 지급 사본의 반복 저장 복원과 패시브 교체.
- 이전 버전의 진행 중 전투 복구에서 카드·전투 더미·난수 보존.
- 이미 존재하는 모호한 D의 보존.
- 과거 강화가 붙은 장비 사본의 같은 무기군 교체 시 보존과 다른 무기군 교체 시 정확한 교환.

집중 회귀 **157개**, 전체 코어 규칙 **224,953개**, 기존 레어 보상·복제·저장 회귀 **17,477개** 검증을 통과했다. 독립 코드 검토에서 추가 수정이 필요한 문제는 발견되지 않았다.
