# v1.0.5 카드 한 장 강화 검증

카드 종류에 공유하던 강화를 덱에서 선택한 사본에 저장한다. 같은 종류의 다른 카드와 이후 획득한 카드에는 적용하지 않으며, 사본별로 한 강화 방향을 선택한다.

## 규칙 검사

[전체 코어 로그](core-tests.log), [컴파일 소스·바이너리 SHA-256과 결과](core-tests-summary.json)

- 기존 전체 규칙 검사와 새 회귀 5묶음: **130,713개 assertion 통과**.
- 중복 카드 중 선택한 한 장의 수치와 코스트만 변경하며, 서로 다른 사본은 독립된 강화 방향을 유지한다.
- 실제 조우로 얻은 새 카드가 미강화인 것을 확인했다.
- 강화 사본의 실제 전투 피해·코스트, 뽑기·버림·소멸·셔플·보관·카드 제거를 확인했다.
- 즉시·다음 턴 무료 연계가 실제 사본을 회수하며, 가넷 재사용은 사용한 사본을 회수·소멸한다.
- 저장과 재로드 및 이전 전체 강화 저장의 사본별 변환을 확인했다. 이전에 적용된 효과는 현재 보유한 사본에 보존하고 신규 획득에는 전파하지 않는다.
- 공유 도감과 상대 기술의 원본 수치는 유지한다. 검사 중 핵심 소스와 바이너리 해시가 동일했다.

전체 코어 검사 이후 제품 코드에서는 `ChooseEventOption`의 `upgrade_card` 안내문 문자열만 수정했다. 안내문은 선택한 한 장만 강화되고 같은 종류의 다른 카드와 이후 획득하는 카드에는 적용되지 않는다고 설명한다.

최신 소스를 다시 컴파일하고 `Tools/RunCoreTests.ps1 -UpgradeOnly`로 `--upgrade-only` 집중 검사를 실행했다. `StrategicUpgradeChoice`와 그 안의 회귀 5묶음, 실제 조우에서 생성한 안내문·로그 검사가 **164개 assertion으로 통과**했다. 전체 검사를 다시 실행하지 않았으며, 추가 변경은 집중 실행 분기와 안내문 검증에 한정된다. [집중 검사 로그](upgrade-focused-tests.log)와 [현재 소스·바이너리 SHA-256 및 범위](upgrade-focused-tests-summary.json)에 기록했다.

## Windows 표시와 배포

[실제 화면 검사](native-ui/coverage.json)는 한 장 선택, 다른 사본 재선택, 강화/일반 상세, 손패, 덱, 사용 전 정보, 모닥불 제거 및 재로드를 포함한다. 강화 사본은 금색 테두리·이름의 `+`·강화 배지로 표시한다.

[배포 빌드](release-build.json), [실행 파일 시작 검사](release-startup.json), [Windows ZIP 파일·SHA-256 검사](windows-package.json)에 결과를 기록한다.

검증은 별도 저장 경로에서 수행하며 개인 원정·연구 저장 파일 4개의 전후 해시를 비교한다. 빌드 중 공간 부족으로 중단된 시도는 [임시 캐시 정리](disk-recovery.json) 후 재시도했으며, [최종 임시 파일 정리](storage-cleanup.json)에 디스크 회수 내역을 기록한다.
