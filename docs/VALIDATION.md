# 아트·전투·카드·지도 검증

## 실험체 간 8종 교차 연계

v0.1.7의 최신 결과는 [연계 검증 기록](validation-cross-synergies/README.md)에 보관한다. 에키온·블레어의 VF 공명, 아이솔·로지·셀린·테오도르의 폭파 연계, 기름 점화·상처·넉백·기동·꽃과 나비·보호 지원을 구현했다. 고유 자원을 유지하면서 실제 지불 코스트, 턴당 생성·발동 및 추가량 상한을 양측 전투·적 예고·저장 재개에 적용한다. 아래 절들은 각 이전 업데이트의 검증 기록이다.

## 짧은 카드 미리보기·이진 상태

검증일: 2026-10-09. Windows, Unity 6000.3.11f1. 이 절이 최신 카드 설명 및 상태 처리 결과다.

카드 392종의 작은 본문과 상세 화면의 요약 탭은 같은 `DescriptionSummary.CardPreview`를 사용한다. 즉시 행동과 핵심 효과를 최대 두 문장 묶음으로 선택하며, 문장 중간을 자르거나 글꼴을 줄이지 않는다. 카드 본문은 11픽셀 글꼴로 직접 표시하며 내부 스크롤이 없다. 전체 설명에는 보조 효과·상한·기간·소모·정화·상태 조건과 공통 규칙을 모두 남긴다. [전체 미리보기와 효과 목록](DESCRIPTION_SUMMARIES.md), [설명 원칙](DESCRIPTION_READABILITY.md)에 기록했다.

실제 Galmuri11 글꼴과 손패·가방·도감·시작 선택·보상·상세 왼쪽 카드의 여섯 크기에서 392종을 기본 수치와 두 자리 전투 수치로 측정했다. **4,704개 측정 모두 본문 높이 안에 들어간다.** 초기 측정에서 긴 문장이 남은 카드를 발견해 보조 효과를 전체 설명으로 옮기고 줄바꿈 여유를 반영한 뒤 최종 재검증했다. 스크롤이나 말줄임표로 부족한 공간을 가리지 않는다. [실제 글꼴 측정](validation-summary-states/preview-layout.json)에 모든 문자열·크기·필요 높이를 보존한다.

59종의 변신·준비·표식·필드 효과를 활성/비활성 상태로 구분했다. `state_on`, `state_off`, `state_toggle`은 수치 증가·설정과 별도 동작이다. 이렘 R은 고양이 상태로 진입하고 다시 사용하면 해제하며, 리오 Q·에스텔 E·제니 E도 명시적인 전환을 사용한다. 필드에는 ‘고양이 상태 · 활성’처럼 표시하고 1/1을 표시하지 않는다. 공격 조건도 ‘고양이 상태이면’·‘장궁 자세 상태가 아니면’으로 설명한다. 통나무·수정·체스말 같은 물리적 자원 및 다중 수치는 유지한다. 기존 저장의 활성 상태, 적 행동 예측용 복제, 전투 초기화와 공통 패시브 발동을 검사했다. [상태 분류와 호환성](BINARY_STATE_MECHANICS.md)에 기록했다.

[핵심 규칙](validation-summary-states/core-tests.log) **45개 시나리오·17,528개 단언**, [설명 감사](validation-summary-states/description-audit.log) **16,400개 단언**이 통과했다. 상태를 숫자나 배율로 표현하는 설명도 없다. 최종 실제 개발 플레이어에서 [게임 화면 62개](validation-summary-states/native-screens.json)를 캡처했고 실행 오류 0개·본문 넘침 0개다. 손패·도감·준비·보상 카드, 이렘의 요약/전체 설명과 상태 진입/해제 화면을 직접 확인했다. 검증은 개인 저장과 다른 전용 슬롯을 사용한다.

최종 [개발 빌드](validation-summary-states/development-build.log)와 [배포 빌드](validation-summary-states/release-build.log)는 오류 0개로 성공했다. 설치된 실행 파일·Unity 런타임·게임 어셈블리·리소스 4개의 해시는 [배포 출력과 같다](validation-summary-states/release-hashes.json). [실제 실행 창과 로그](validation-summary-states/release-startup.json)는 정상이며 개인 이어하기 저장의 설치 전후 해시도 같다. [배포 ZIP](validation-summary-states/archive-validation.json)은 런타임 180개 파일의 CRC·SHA-256 및 누락 검사를 통과했다. 배포 버전은 `v0.1.1`이며 기존 `v0.1.0`도 보존한다.

## 얼굴 개성·설명 요약·상대 장비와 무기 스킬

검증일: 2026-10-09. Windows, Unity 6000.3.11f1. 아래의 과거 기록보다 이 절의 결과가 최신이다.

하나와 실험체 91명의 스프라이트 92개를 개별 원본 얼굴·표정·눈매 참고 자료를 바탕으로 다시 제작했다. 160×160 투명 PNG를 최근접 보간으로 표시하며, 이전의 80픽셀 축소를 새 스프라이트에 적용하지 않는다. 캐릭터별 눈꺼풀·눈썹·입·연령·안경·마스크 차이를 [얼굴 설계](art-identity/face-designs.json)에 기록했고 전체 몸 8페이지와 얼굴 확대 8페이지를 직접 검토했다. [전체 아트 감사](art-identity/validation.json)는 92개 모두 완전하며 누락·중복·프롬프트 및 원본 해시 불일치가 없다. 장비 18개와 무기 기술 14개의 아이콘도 개별 원본 참고 자료에서 제작했다. 최종 장비는 47개, 무기군은 23개이며 [제작 기록](art-system/loadout-art-manifest.json)에 출처·생성 원본을 보존한다.

카드 392개·패시브 91개·룬 16개·장비 47개에 공통 요약 생성기를 사용한다. 미리보기와 상세의 요약 탭은 같은 설명을 표시하며, 전체 설명 탭에서 원래 변환 규칙을 확인한다. 긴 요약은 스크롤로 모두 볼 수 있다. 발동 조건·수치·소비·횟수·상한·기간은 남기고 동일한 문장은 중복 제거하며 자원은 ‘1 증가’, ‘1로 만듭니다’처럼 수치로 표현한다. 가산 효과는 중복 제거로 사라지지 않도록 별도 검사했다. 설명 감사 [8,441개 단언](validation-identity-art/description-audit.log)이 통과했다. 니아 W의 요약에 블록 ×4, 최대 추가 피해 12, 소모, 다음 Q 할인과 상태 조건이 모두 표시되는 것도 원본 캡처에서 확인했다.

상대 실험체는 자신의 Q/W/E/R뿐 아니라 기본 공격·기본 경계·본인 무기군의 D·무작위 F를 가진다. 자신의 패시브도 적용하며 일반 실험체는 레벨 8/14/18부터 각각 1/3/5개 장비를, 보스는 진행에 따라 2/3/5개 장비를 갖춘다. 상대 정보에서 ATK/D/F·패시브·장비를 확인할 수 있다. 시작 카드 후보는 코스트 0~4로 제한하고 리롤 시 이미 선택한 카드와 위치를 보존한다. 중앙의 회피·상태 표시를 없애고 양측 필드 효과 및 필드 상세로 모았다.

장비는 고유 조건·상한·지속·치유 감소·방어 관통·정화·피해 유예 같은 효과로 구분한다. 무기 장착으로 D를 자동 지급하고 알렉스 패시브는 장착한 무기마다 다른 무기군의 D를 한 장 더 지급한다. 장비·패시브 교체 시 자동 지급한 카드만 갱신하며 보상으로 획득한 D는 보존한다. 아오자이의 유예 피해는 실제 체력 피해 일부를 다음 자신의 3턴 시작에 나눠 적용하고 필드에 남은 피해·턴을 표시한다. 상세 규칙은 [장비·무기 설계](EQUIPMENT_LOADOUTS.md)에 기록한다. 오브젝트 확률은 늑대 25%, 곰 35%, 키오스크 주변 실험체 25%로 낮췄다.

최종 [핵심 검증](validation-identity-art/core-tests.log)은 **44개 시나리오·17,065개 단언**을 통과했다. 시작 후보·고정 리롤·상대 ATK/D/F·본인 패시브·후반 장비·D 지급 및 회수·획득 D 보존·알렉스·장비 효과와 피해 유예·이전 저장 복원을 함께 검사했다. [40개 시드 자동 플레이](validation-identity-art/balance.log)는 탈출 13회·패배 27회·정체 0회였다. 이는 HP·난수·적 상태를 수정하지 않는 고정 전략의 결과이며 사람의 승률 추정은 아니다.

최종 개발 플레이어에서 게임 화면 **57개**와 아트 **23페이지**를 캡처했다. 실제 리소스는 스프라이트 92개·기술 및 패시브 아이콘 483개·시스템 아이콘 70개이며 누락 0개다. 모든 캡처는 1280×720으로 비어 있지 않고 실행 오류는 0개다. 요약·전체 설명, 고정 선택, 상태 필드, 상대 장비, 알렉스 D, 장비 제작과 새 얼굴을 직접 검토했다. [화면 집계](validation-identity-art/native-screens.json), [게임 화면](validation-identity-art/native-ui/), [아트 페이지](validation-identity-art/native-art/)를 보존한다. 검증 플레이어는 개인 저장과 다른 전용 슬롯을 사용했다.

최종 Windows [개발 빌드](validation-identity-art/development-build.log)와 [배포 빌드](validation-identity-art/release-build.log)는 모두 `LUMIA BUILD Succeeded / errors=0`이다. 설치한 실행 파일·Unity 런타임·게임 어셈블리·리소스 4개의 SHA-256은 [배포 출력과 모두 같다](validation-identity-art/release-hashes.json). 실제 실행 창 제목 `Black The Survival`과 응답이 정상이고 시작 오류는 0개다. 개인 이어하기 저장은 정상 종료 후 백업하고 설치 전후 SHA-256이 같음을 확인했다. [실행·저장 확인](validation-identity-art/release-startup.json)을 보존하며 설치된 게임은 실행해 두었다. 빌드 프로세스에만 Burst 컴파일 비활성화를 적용하고 원본 프로젝트 설정은 유지했다.

## 시스템 아이콘·굵은 도트·난도·조우·원본 상태

검증일: 2026-10-09. Windows, Unity 6000.3.11f1.

룬 16개·장비 29개·오브젝트 5개·크레딧·모닥불의 시스템 아이콘 **52개**를 원본 참고 이미지별로 새로 제작했다. 개별 생성 원본과 프롬프트, 출처·해시는 [제작 기록](art-system/README.md)에 보존한다. 32픽셀 논리 격자, 28픽셀 내용 영역과 사방 2픽셀 여백을 64픽셀 PNG로 확대해 2×2 도트를 유지한다. 하나와 실험체 91명의 스프라이트 **92개**도 높이 80픽셀로 바꾸고 얼굴·의상·무기·두 인물의 구도를 전체 8페이지에서 확인했다. 원본 그림과 기존 스킬·패시브 아이콘은 함께 보존한다.

`Tools/ValidateSystemArt.py`는 52개 아이콘과 92개 스프라이트의 전체 범위·RGBA·투명도·크기·내용 여백·픽셀 격자·원본·해시·중복 검사를 통과했다. [결과](art-system/validation.json)는 `passed: true`, `complete: true`, 오류·경고 0개다. 실제 개발 플레이어의 전체 아트 검증도 전용 스프라이트 92개·기술 및 패시브 아이콘 469개·시스템 아이콘 52개, 누락 0개를 확인했다. 시스템 아이콘 2페이지의 실루엣·색·명칭도 직접 확인했다.

치유 드론은 **실제 체력 피해 후 `체력 × 3 ≤ 최대 체력`**이면 2턴 동안 턴 종료마다 2 회복한다. R 사용으로 발동하지 않으며 재발동 대기 시간은 자신의 3턴이다. 정확히 1/3·바로 위·반복 피해·R 사용을 검사했고 실제 플레이어에서도 저체력 피격 후 드론 상태를 확인했다.

적 체력은 야생동물의 초반 +15%와 막별 성장, 일반 실험체의 막별 증가, 보스의 더 큰 증가로 조정했다. 마지막 막 레벨 20의 일반 실험체는 302HP, 보스는 558HP다. 전투 크레딧은 `(야생48/실험체80/보스185) + 레벨×5 + 0~24 무작위 + 보상 보정`으로 줄였다. 경험치와 재료 구매 가격 200/200/250/350/500은 유지한다. 전체 수식은 [백엔드 집계](validation-system/backend-summary.json)에 있다.

실험체 91명의 조우·273개 행동을 재구성하고 고정 스킬 보상 108개·음식 보상 8개·대가가 있는 행동 33개를 연결했다. 이름·슬롯·코스트·상세 미리보기와 정확한 지불·소모량을 별도 줄에 표시한다. 크레딧 부족, 체력 소모 후 사망, 제거·강화 대상이 없는 선택은 비활성화한다. 실제 데이터 초기화 감사 1,556항목을 통과했다. [전체 조우](EVENT_IDENTITY.md)에 상황·선택·참고 자료를 기록한다.

원본 상태 20종을 카드 **207종**에 연결했다. **이동 카드 85종**에는 속박·둔화의 이동 제한과 코스트 증가가 적용된다. 기절·제압·빙결·정지, 침묵·속박·실명·공포·변이·춤 등을 다른 행동으로 변환하고 중첩·기간·정화·수면 및 빙결 해제·원본 스택 조건·설치물 적중을 검사했다. 준비된 다음 기본 공격 상태는 첫 공격이 빗나가도 강화 본체와 함께 소비한다. 일반 중독을 임의로 주는 카드는 0개이며 출혈·화상은 원본 이름의 기존 지속 효과를 사용한다. [변환 규칙](STATUS_IDENTITY.md)에 세부 설명을 기록한다.

최종 규칙 검증은 **41개 시나리오·12,740개 단언**을 통과했다. [핵심 로그](validation-system/core-tests.log), [40개 시드 자동 플레이](validation-system/balance.log)는 탈출 **25회**, 패배 **15회**, 정체 **0회**다. 변경 전 같은 정책은 탈출 30회·패배 10회였다. 자동 플레이는 실제 공개 행동만 사용하며 HP·난수·적 상태를 직접 수정하지 않는다. 이는 고정 전략의 비교 결과다.

## 기술·패시브·룬의 고유 효과

## Black The Survival 이름·패시브 확률

검증일: 2026-10-09. Windows, Unity 6000.3.11f1.

로비 제목, Unity 제품·창 이름, 편집기 메뉴와 배포 실행 파일을 **Black The Survival**로 변경했다. 실행 파일은 `Build/Windows/BlackTheSurvival.exe`다. 이전 이름의 저장·백업은 새 저장이 없을 때만 가져오고 원본은 보존한다. 환경 설정은 음량·효과음·모션의 알려진 키만 가져오며 새 설정이 있으면 덮어쓰지 않는다. 자동 검증은 개인 저장·설정 이전을 건너뛴다.

현재 보유 패시브의 주인 Q/W/E/R 카드는 시작 드래프트·카드 리롤·야생동물 보상의 무작위 선택지에서 가중치 3, 나머지 카드는 가중치 2로 추첨한다. 즉 개별 후보의 가중치는 1.5배이며 전체 확률은 후보 구성에 따라 달라진다. 여러 패시브의 주인에게 각각 적용하고 같은 주인의 중복 패시브는 중첩하지 않는다. 카드는 중복 없이 추첨한다. 고정 실험체 보상, 지정 이벤트 카드와 전투 손패 셔플은 기존 규칙을 유지한다.

새 시작 드래프트는 저장되는 별도 seed를 사용한다. 같은 패시브 재선택은 카드 목록과 선택을 보존하며, 왕복 변경은 같은 결과를 재현하고 전역 RNG나 카드 리롤을 추가로 소비하지 않는다. 패시브 변경으로 선택지에서 빠진 카드만 선택에서 해제된다. seed가 없는 이전 v1/v2 준비 저장은 기존 목록과 선택을 보존하고 명시적 카드 리롤부터 새 방식으로 전환된다. 패시브 교체는 이후 무작위 추첨에 즉시 반영된다.

핵심 테스트는 **23개 시나리오·10,713개 단언**을 통과했다. 두 후보를 2만 회 추첨한 검증에서 균등 후보는 10,036회(50.18%), 패시브 주인 후보는 12,015회(60.075%)로 등장하여 3:2 가중치의 기대값을 확인했다. 초기 선택과 리롤, 중복·무효 패시브, 다중 소유자, 후보 중복 제거, 교체, 이전 준비 저장, 저장 후 RNG 연속성 및 고정 보상·손패를 확인했다. 독립적인 코드 검토도 통과했다. 40개 seed의 자동 플레이는 탈출 33회·패배 7회·정체 0회다.

실제 창을 표시한 개발 플레이어에서 20개 화면을 캡처했다. 모든 이미지가 1280×720이며 빈 프레임이 없다. 새 로비 제목, 시작 패시브·패시브 가방·교체 화면의 추가 안내를 눈으로 확인했고 런타임 예외는 없었다. 그림은 `screenshots/`에 있다. 이번 빌드는 일시 AOT 디스크 공간 문제를 해결하기 위해 빌드 프로세스에만 `--burst-disable-compilation`을 적용했다. 게임의 규칙·UI는 Burst를 사용하지 않으며 프로젝트 설정과 API 호환 레벨은 바꾸지 않았다.

## 데포르메 스프라이트·스킬 아이콘

검증일: 2026-10-08. Windows, Unity 6000.3.11f1.

실험체 91명과 하나의 개별 도트 스프라이트 92개, 카드 아이콘 378개, 패시브 아이콘 91개를 적용했다. 총 561개 PNG와 36개 생성 원본의 전체 참조·크기·투명도·경계·원본 출처·픽셀 중복 검사가 통과했으며 누락, 중복, 오류와 경고는 모두 0개다. 검사 결과는 `art-chibi/art-validation.json`, 제작 도구와 실제 프롬프트 기록은 `ART_CHIBI.md`와 `art-chibi/prompts.json`에 있다.

실제 Unity 개발 플레이어에서 전용 스프라이트 92개와 아이콘 469개를 모두 불러왔다. `-lumia-art-verify`의 결과는 `Dedicated sprites: 92`, `Dedicated icons: 469`, `Missing assets: 0`이다. 스프라이트 8페이지와 아이콘 12페이지를 눈으로 확인하여 얼굴·몸체·무기의 잘림, 옆 칸 혼입, 대체 그림과 이름 오류가 없음을 확인했다. 클로에·니나와 데비·마를렌은 두 몸체와 소품이 모두 표시된다. 캡처와 집계는 `art-chibi/native/`에 있다.

새 그림을 사용한 실제 게임 화면 17개도 캡처했다. 시작 선택, 전투, 보상 선택·취소, 무료 연계, 카드 상세, 조우, 도감과 가방에서 그림 및 설명의 가독성을 확인했다. 하나의 공격, 아야의 사격과 샬럿의 회복 연출에 새 아이콘이 표시된다. 캡처 로그에 런타임 예외가 없으며 그림은 `screenshots/`에 있다. 검증 실행은 전용 저장 경로를 사용했다.

Unity 런타임·에디터 C# 컴파일과 Windows 개발·배포 빌드가 통과했다. 최종 배포 빌드 결과는 `LUMIA BUILD Succeeded / errors=0`이며 실행 파일은 `Build/Windows/LumiaVFLoop.exe`다. 도트 그림은 Point 필터, 밉맵 없음, 비압축 픽셀과 원본 알파를 사용한다. 이번 아트 교체는 전투 규칙과 기존 저장 형식을 바꾸지 않는다.

## 전투·카드·지도 확장

검증일: 2026-10-08. Windows, Unity 6000.3.11f1.

`Tools/RunCoreTests.ps1`에서 **22개 시나리오, 10,534개 단언**을 통과했다. 실험체 91명 모두 Q/W/E/R·패시브·고유 조우가 연결되며, 카드 378종의 참조·코스트·문장형 설명·효과 설정을 확인했다.

- 보상 선택을 다시 눌러 취소할 수 있다. 취소하면 예산이 돌아오며 확정 전에 덱은 변하지 않는다. 확정은 한 번만 추가한다.
- 코스트는 0~7, 플레이어와 적의 최대 코스트는 레벨에 따라 5~8이다. 새 지도는 12구역 × 3막이며 전투 중심 생성 경로의 28승으로 레벨 20에 도달했다.
- 무료 사용권은 코스트가 0이어도 적용된다. 실제 보유한 카드만 회수하며 소멸한 카드나 미보유 카드를 만들어내지 않는다. 턴 만료·적중 조건·자기 및 상호 연계 제한을 확인했다.
- 수아 R은 다른 실험체의 카드를 사이에 사용해도 마지막 수아 Q/W/E를 다시 사용할 수 있다.
- 적이 적중 조건의 회수 스킬을 빗맞히면 예정된 무료 연계를 취소한다. 다단 공격에서 일부가 적중하면 연계가 유효하다.
- 적의 기술을 한 장씩 실행한다. 행동 중 저장을 복원해도 다음 카드·피해·난수가 일치하며 마지막 타격 효과는 사망·승리 후에도 전달된다.
- 버전 1 저장의 7구역 지도와 진행을 보존한다. 이미 받은 보상 카드를 선택 상태로 이전하며 당시 획득 가격·총 예산을 유지한다. 반복 복원해도 덱에서 추가 카드가 빠지지 않는다.
- 기존 시작 선택·리롤·룬 잠금·연결 이동·드롭·상점·장비 슬롯·요리 횟수·패시브 교체·상태·승리·패배 규칙도 통과했다.

최신 40시드 자동 플레이는 **탈출 30회·패배 10회·진행 정체 0회**다. 공개 API로 실제 선택·이동·카드·보상·제작·회복을 수행하며 HP·난수·적 상태를 직접 수정하지 않는다. 이는 고정 전략의 결과다. 고코스트 카드를 일찍 선택하거나 방어·회피 없이 전투를 연속 진행하면 초반 패배도 가능하다.

Unity 런타임 C# 컴파일과 Windows 개발·배포 빌드를 통과했다. 최종 빌드 로그는 `LUMIA BUILD Succeeded / errors=0`이다. 실제 플레이어에서 17개 화면을 캡처했으며 로그에 런타임 예외가 없었다. 보상 선택·취소의 예산과 강조 표시, 코스트 0의 무료 카드, 12구역 지도의 앞·뒤 스크롤, 전체 문장 상세 기록, 하나의 아케이드 공격·아야의 연속 탄환·샬럿의 회복 효과를 눈으로 확인했다. 그림은 `docs/screenshots/`에 있다. 최종 실행 파일은 개발 표시를 끈 `Build/Windows/LumiaVFLoop.exe`다.

## 첫 버전 기록

검증일: 2026-10-08. 환경: Windows, Unity 6000.3.11f1.

## 게임 규칙

`Tools/RunCoreTests.ps1`에서 **18개 시나리오, 8,552개 단언**이 통과했다. 데이터 참조, 시작 선택과 리롤 한도, 룬 변경 제한, 연결 지도 이동, 손패·뽑기·버리기·소멸, 코스트와 상태 효과, 상대 Q/W/E/R 구성, 중복 보상 방지, 동물별 오브젝트 드롭과 실험체 주변 드롭, 상점 가격, 장비 슬롯·교체·무기 카드 동기화, 요리 횟수, 패시브 교체, 90개 이벤트 선택지, 전투 중 상태 복원과 난수 재현, 레벨 20, 3막 탈출 및 패배를 확인했다.

적 행동 예고는 약화와 예정된 카드의 순차 힘 증가를 반영한다. 예고를 반복 조회해도 난수·덱·예정 행동은 바뀌지 않으며, 회피·방어가 없는 검증 전투에서 예고 피해와 실제 피해가 일치한다.

## 실제 행동을 사용하는 자동 플레이

`Tools/RunCoreTests.ps1 -Balance`는 시작 선택, 이동, 카드 사용, 턴 종료, 보상, 구매, 제작, 회복 등을 공개 게임 API로 수행한다. HP·난수·적 상태를 직접 수정하지 않는다.

- 시드 1~40: 탈출 **38회**, 패배 **2회**, 진행 정체 **0회**.
- 탈출한 플레이의 최종 레벨은 18~20이며 장비는 4~9개.
- 실제 생성 지도에서 전투 중심 경로를 진행하여 18승 후 경험치로 레벨 20에 도달했다.

이는 해당 자동 플레이 전략에 대한 결과이며 모든 선택 조합의 승리를 보장하는 값은 아니다. 현재 수치는 시스템을 체험하기 쉬운 첫 버전으로 조정했다.

## 컴파일·빌드·화면

- `Tools/VerifyRuntime.ps1`: Unity 런타임 소스 C# 컴파일 통과.
- 원본 Unity 프로젝트를 유지하고 별도 복사본에서 Windows 실행 파일 빌드 성공, 빌드 오류 0개.
- 실제 Windows 플레이어에서 로비, 시작 카드 선택, 지도, 전투, 키오스크, 제작 모닥불, 실험체 조우, 카드 도감, 가방의 9개 화면을 캡처했다. 캡처 실행 로그에 런타임 예외가 없었다.
- 캡처는 개발 빌드로 수행했으며 그림은 `docs/screenshots/`에 있다. 최종 배포용 실행 파일은 개발 표시를 끈 빌드다.
- 한글 픽셀 글꼴, 도트 아틀라스 읽기·점 필터, 카드 가독성, 음식 아이콘, 캐릭터 잘림과 안내 문구를 확인했다.
- 가방과 배경 상점·모닥불의 스크롤 상태를 분리했다. 모달이 열려 있을 때 배경 버튼은 작동하지 않는다. 손패가 많으면 카드를 작게 줄이는 대신 가로로 스크롤한다.

## 남아 있는 확장 범위

첫 버전의 전투 실험체 10명·조우 전용 80명 제한은 전투·이벤트 확장으로 해소했다. 이후 데포르메 아트 작업에서 실험체 91명과 하나의 개별 스프라이트, 카드 378개와 패시브 91개의 전용 아이콘을 모두 제작했다. 더 많은 무기군과 장비, 장기적인 난이도 조정은 확장할 수 있다. 원본의 적용 시점은 `SOURCES.md`, 추가 81명의 공식 스킬 자료는 `ROSTER_CLASSIC.md`와 `ROSTER_RECENT.md`, 도트 효과와 그림은 `ART.md`, 최신 제작 기록은 `ART_CHIBI.md`를 참고한다.
