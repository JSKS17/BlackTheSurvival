# 카드와 기록 화면 성능 개선

v1.0.11은 보유 덱·카드 강화 화면에서 시작해 같은 방식으로 비용이 반복되던 UI를 함께 최적화한다.

- 보유 덱, 강화 후보, 모닥불 카드 제거, 레어 조우 카드 제거·복제는 전체 스크롤 높이와 실제 덱 번호를 유지하면서 현재 보이는 카드만 그린다.
- 카드 표시 정의와 설명은 원본 정의 및 강화 분기로 구분해 재사용한다. 일반·강화·레어 강화의 효과가 섞이지 않으며, 새 판에서 같은 인스턴스 번호를 다시 사용해도 현재 판의 강화 분기를 확인한다.
- 카드 요약은 실제 피해·방어·회복 수치가 바뀌면 다시 만든다. 코스트, 충전, 상태이상, 사용 가능 여부와 선택 표시는 계속 현재 전투 값을 사용한다. 캐시의 항목 수에는 상한이 있다.
- 강화 방향별 미리보기, 도감 검색문과 결과, 정적 패시브·룬·장비 설명, 텍스트의 native 높이 측정 결과를 재사용한다. 글꼴이 다시 만들어지면 높이를 다시 측정한다.
- 연구 일지, 전투 기록, 가방의 음식, 보유 룬·증강, 무한 모드의 장비와 장비 교체 목록도 가시 범위만 처리한다. 기록의 필터·확장 상태와 실제 데이터가 달라지면 배치를 다시 계산한다.
- 전투 손패와 소멸·교환 선택창은 화면에 보이는 열만 그린다. 필드 상세의 출처 검색은 실험체·자원 키로 재사용한다.
- 지도는 연결 관계를 재사용하고 화면에 걸치는 노드와 연결선을 그린다. 화면 밖에 있는 양 끝점을 연결하는 선도 화면을 통과하면 유지한다.

## 검증 조건

실제 Windows 개발 플레이어의 전체 `LumiaGame.OnGUI`에서 Layout·Repaint CPU 시간을 측정한다. 고정 시드, 덱 102장·서로 다른 참조 96개·강화 후보 78장·전투 기록 240행을 사용한다. 12개 화면마다 20프레임을 준비한 뒤 이벤트를 60회 이상 수집한다. 저장·연구 기록은 일반 플레이와 분리된다.

비교 결과는 작업 공간의 `Build/Release111Verification/native-list-performance-*.json`과 `native-list-performance.json`에 보존한다. 이 수치는 해당 Windows GUI 구간의 CPU 시간이며 웹 FPS 또는 전체 프레임 시간으로 환산하지 않는다. Unity Mono의 할당 계수가 0만 반환하면 측정 불가로 기록한다.

최종 개발 빌드의 Repaint 평균은 다음과 같다. 목록의 상·중·하단 또는 강화 선택 상태의 범위를 함께 적었다.

| 화면 | 이전 | 개선 후 |
| --- | ---: | ---: |
| 보유 덱 | 296.9~313.1ms | 6.00~6.88ms |
| 카드 강화 | 159.9~165.6ms | 1.35~1.48ms |
| 모닥불·레어 카드 제거 | 298.2~299.2ms | 2.11~2.32ms |
| 도감 | 16.47ms | 7.31ms |
| 연구 일지 | 13.50ms | 5.61ms |
| 전투 기록 | 8.61ms | 5.02ms |
| 지도 | 7.52ms | 4.66ms |

보유 덱은 96개 참조 전체에서 현재 화면의 12개로, 강화 후보는 78장에서 6장으로, 휴식·레어 제거 목록은 102장에서 12장으로 렌더링 작업이 줄었다. 임의 스크롤 위치의 부분 행도 포함하며, 원래 전체 목록 높이는 유지한다. 12개 뷰의 16개 영역을 비교한 5,035,009픽셀 중 149픽셀만 채널 값 최대 1/255 차이가 있었고, 실제로 검토한 덱·강화·연구·기록·레어 화면에서 배치·문구 회귀는 보이지 않았다.

표시 정의·요약과 검색을 원본 결과와 대조하고, 같은 개수에서의 덱 교체·강화 분기 변경·새 원정의 인스턴스 번호 재사용·가시 범위의 절대 인덱스를 검증한다. 기존 개발 플레이어의 카드 레이아웃 및 강화·모닥불·레어 조우·연구·증강 122개 화면 검증도 다시 실행한다. 긴 연구 보고서 해금 안내는 스크롤로 끝까지 읽을 수 있도록 수정하고, 실제 상단·하단을 따로 확인한다. 측정과 화면 검증 자료는 배포 ZIP에 포함하지 않는다.
