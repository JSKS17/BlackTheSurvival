# 모닥불 무기 제작 성능 개선

무기 목록은 28종이며 다른 장비 부위는 6~8종이다. 이전 화면은 Unity의 각 OnGUI 이벤트마다 28종 전체의 설명을 만들고 다시 정규화한 뒤 글자 높이를 측정했다. 화면 밖 항목도 같은 작업과 내부 스크롤 구성을 반복했다.

`CraftingCatalog`는 장비 설명·검색문·태그를 한 번 준비하고, 부위·검색어·선택 태그가 바뀔 때만 필터 결과를 갱신한다. `LumiaCraftingUI`는 설명의 GUIContent와 높이 측정 결과를 재사용한다. 글꼴 재구성 시에는 높이 캐시를 갱신한다. 전체 스크롤 높이를 유지하면서 현재 보이는 행의 항목만 그린다.

## 검증

- 실제 57종 장비의 원래 검색·태그 결과와 표시 설명을 대조했다. 스크롤 경계와 장비 제작·교체·모닥불 동작을 포함한 집중 검사 35,694개가 통과했다.
- 같은 노트북의 Windows 개발 빌드에서 상단·중간·하단마다 Layout 및 Repaint 이벤트를 120회 측정했다. 워밍업 30프레임은 제외했다.
- 이전 Repaint 평균은 68.62 / 68.82 / 78.16ms였다. 개선 후 평균은 1.58 / 1.45 / 1.31ms였다. 그리는 항목은 각각 28개에서 6 / 6 / 4개로 줄었다. 임의 스크롤 위치의 최대치는 9개이다.
- 이전과 개선 후 상단 목록의 화면 픽셀은 동일했다.
- Unity Mono의 스레드별 할당 계수는 0을 반환하여 할당량 측정에 사용하지 않았다. 0을 개선 수치로 간주하지 않는다.

이 수치는 검증용 Windows 빌드의 해당 GUI 구간 CPU 시간이다. 웹 브라우저의 FPS 또는 전체 프레임 시간으로 환산하지 않는다. 실제 키보드·마우스 자동 입력 도구는 초기화에 실패하여 입력 자동화 대신 위치별 렌더링과 기능 회귀 검사로 확인했다.

원본 측정과 비교 결과는 개발 작업 공간의 `Build/Release110Verification/native-craft-performance-*.json` 및 `native-craft-performance.json`에 보존한다. 검증은 별도 저장 경로를 사용하며 개발 측정 파일은 배포 ZIP에서 제외한다.
